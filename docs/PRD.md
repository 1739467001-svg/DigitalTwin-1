# PRD · 城市轨交车站数字孪生（视觉模拟优先）

> 文档角色：回答"做什么、为谁做、做到什么程度算完成"。
> 技术实现见 [SPEC.md](./SPEC.md)，里程碑排期见 [../PLAN.md](../PLAN.md)。

## 1. 背景与目标

### 1.1 背景

作者已有一系列"模拟现实"风格的 3D 可视化作品（智慧港口、天府机场 A/B 影子仿真、海上油田钻井平台、会议室 3D 孪生），风格统一：真实基础设施 + 持续运营数据 + 深色工业 HUD。本项目补上"城市交通"一块。

### 1.2 目标（按优先级）

1. **视觉吸引力第一**：项目的首要价值是吸引和震撼观看者，作为作品集的展示品。
2. **行为可信**：列车、客流、设备的行为符合真实地铁运营直觉，经得起懂行的人看 5 分钟。
3. **保留升级为真孪生的接口**：仿真内核与数据源解耦，未来可接真实时刻表/闸机流量。

### 1.3 非目标（本期明确不做）

- 不接入任何真实数据源；
- 不做换乘站、多站线网；
- 不做移动端适配（桌面浏览器优先）;
- 不追求写实级渲染（不引入重型 3D 资产、贴图库）。

## 2. 目标用户与使用场景

| 用户 | 场景 |
|---|---|
| 观看者（老师/评委/访客） | 打开链接或看投屏，10 秒内被画面抓住，2 分钟内看懂"这是一个会呼吸的地铁站" |
| 作者本人 | 展示时开"导演模式"自动运镜；答辩时手动操作故障注入/限流演示因果链 |
| 未来的开发者（含 AI 助手） | 依据文档扩展功能、接入真实数据 |

### 核心演示脚本（验收时按此走查）

1. **开场**：页面加载 → 镜头 fly-in 进入剖面站体 → 深色场景、辉光、反光地面，第一印象成立；
2. **日常运营**：列车进站演出（头灯扫隧道 → 警示灯闪 → 减速对标 → 门联动 → 人流交换）；
3. **早高峰**：时间轴拖到 8:00，进站洪峰、站台密度爬升、热力图变红、触发预警；
4. **干预**：注入扶梯故障 → 客流改道拥堵加剧 → 启动限流 → 密度曲线被压回；
5. **对比**：开 A/B 影子仿真，两套策略并跑，KPI 对比一目了然。

## 3. 功能需求

优先级：P0 = 该里程碑验收必须，P1 = 应有，P2 = 可延期。

### FR-1 场景与站体（M1）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-1.1 | 三层剖切站体：地面层（4 出入口）、站厅层（安检/售票/闸机/楼扶梯）、站台层（岛式站台/屏蔽门/双向轨道） | P0 |
| FR-1.2 | 轨道相机（OrbitControls）+ 至少 4 个预设机位平滑切换（全景/站厅/站台/跟车） | P0 |
| FR-1.3 | 楼层聚焦：点击楼层或设备，镜头推近并高亮 | P1 |

### FR-2 列车（M1 基础 / M2 演出）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-2.1 | 双向列车按行车间隔到发（高峰 150s / 平峰 360s），加减速曲线对标停车，停站 30–45s | P0 |
| FR-2.2 | 车门与屏蔽门联动开闭，乘客按车门位置上下车 | P0 |
| FR-2.3 | 进站演出：隧道头灯光束 → 屏蔽门警示灯闪烁 → 进站镜头微震 → 离站尾灯 | P0(M2) |
| FR-2.4 | 载客率可视化：车厢颜色深浅表示满载程度 | P1 |

### FR-3 客流（M1 单向 / M2 完整）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-3.1 | 个体客流：低模小人 InstancedMesh 渲染，峰值 ≥ 1500 人在站 | P0 |
| FR-3.2 | 完整旅程状态机：入口→安检排队→闸机→扶梯→站台候车（按车门聚簇）→上车；出站反向 | P0 |
| FR-3.3 | 全天 24h 到达率曲线（早晚双峰），泊松到达，OD 比例可调 | P0(M2) |
| FR-3.4 | 客流密度热力图叠加在站厅/站台地面，近看个体、远看热力 | P0(M2) |
| FR-3.5 | 按状态着色（进站/出站/候车），行走带起伏动画 | P1 |

### FR-4 时间系统（M2）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-4.1 | 仿真时钟：1×/8×/60× 变速 + 暂停 | P0 |
| FR-4.2 | 24h 时间轴拖拽跳转（快进重算），固定随机种子可复现 | P0 |

### FR-5 运营 HUD（M1 基础 / M2 完整）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-5.1 | 顶栏：仿真时钟、在站人数、进/出站速率、变速控制 | P0 |
| FR-5.2 | 指标面板：站台密度（人/m²，三级预警）、列车满载率、平均候车时间、留乘率，含迷你趋势线 | P0(M2) |
| FR-5.3 | 设备列表：闸机/扶梯/屏蔽门逐台状态，点击定位镜头 | P1 |
| FR-5.4 | 事件日志：带仿真时间戳的运营事件流 | P1 |

### FR-6 故障与限流（M3）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-6.1 | 故障注入：手动使指定扶梯/闸机组停机，客流实时改道 | P0 |
| FR-6.2 | 密度分级预警：>2.5 人/m² 触发红色告警，全场情绪化光效（色调偏移+灯带脉动） | P0 |
| FR-6.3 | 限流措施：手动/自动关闭部分进站闸机、扶梯改向，密度回落可观测 | P0 |

### FR-7 A/B 影子仿真（M4）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-7.1 | 同一随机种子并跑两套策略（固定间隔 vs 动态加开；不限流 vs 分级限流） | P0 |
| FR-7.2 | KPI 对比面板：最大站台密度、平均候车时间、留乘率 | P0 |

### FR-8 展示性功能（M2–M4）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-8.1 | 导演模式：无操作 30s 后自动运镜（推轨环绕/切进站/跟拍乘客），任意输入退出 | P0(M3) |
| FR-8.2 | 细节动效：扶梯梯级转动、闸机翼门+通过闪光、PIS 屏下一班倒计时 | P1(M2) |
| FR-8.3 | 音效层：进站轰鸣、到站提示音、环境底噪（默认静音，一键开启） | P2(M4) |
| FR-8.4 | 开场 fly-in 镜头 | P1(M4) |

## 4. 非功能需求（NFR）

| 编号 | 需求 |
|---|---|
| NFR-1 | **性能**：1080p 全效果稳定 60fps（近 5 年主流独显/核显）；agent ≤ 2000 时不降帧 |
| NFR-2 | **零构建**：纯 ES Modules + vendor 依赖，`file://` 之外任意静态服务器可跑，可直接部署 Vercel |
| NFR-3 | **确定性**：同一种子 + 同一操作序列 → 完全相同的运行结果 |
| NFR-4 | **浏览器**：Chrome/Edge 最新两个大版本；不承诺 Safari/移动端 |
| NFR-5 | **加载**：首屏可交互 < 3s（无重型资产，全程序化建模） |
| NFR-6 | **界面语言**：中文 |

## 5. 验收标准

每个里程碑统一两条硬标准：

1. **十秒测试**：投屏给一个没看过的人，前 10 秒他会停下来看；
2. **性能红线**：全效果 60fps，无控制台报错。

外加该期 P0 功能逐条走查（见第 3 节编号）。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 人群观感假（穿模、漂移、机器人感） | 不追写实：镜头语言押在闸机队列/扶梯/屏蔽门候车三个"有序场景"；宏观交给热力图 |
| Bloom + 千人 instancing 性能塌方 | 性能预算写进 SPEC；bloom 半分辨率；agent 上限硬编码；每期跑 FPS 探针 |
| 范围蔓延（想加的东西太多） | PRD 非目标条款 + P2 一律延期；新想法先进 PLAN.md 的"后续留门" |
| "震撼感"无法纸面验收 | 每期结束出截图/录屏走查演示脚本，主观验收由作者本人做 |
